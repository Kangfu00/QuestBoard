# The Questboard — กฎสำหรับ Agent

Questboard เป็นโต๊ะนายทะเบียนกิลด์สำหรับจัดการเควส ใช้ native ES modules (`.mjs`) และ CSS ไม่มี dependency สำหรับรันและไม่มี build step เซิร์ฟเวอร์ Node เสิร์ฟ `dist/` และเขียนไฟล์สำรองในเครื่อง

ใช้ภาษาไทยสำหรับข้อความ UI และการสื่อสารกับผู้ใช้ ใช้ชื่อโมดูลและศัพท์เทคนิคตามโค้ด เริ่มจาก [AGENTS.md](../../AGENTS.md) แล้วเลือกอ่านกติกาตามงาน ถ้า README หรือสเปกย้อนหลังต่างจากโค้ด ให้ตรวจ entry point, โมเดล และเทสต์ที่เกี่ยวข้องก่อนตัดสินว่าพฤติกรรมใดใช้อยู่จริง ให้คำขอล่าสุดของผู้ใช้กำหนดขอบเขตการเปลี่ยน

## โครงสร้างโปรเจกต์

- `dist/index.html` กำหนดลำดับ CSS และโหลด `dist/app.mjs` ซึ่งเชื่อม UI, state และโมดูลฟีเจอร์ `dist/` คือซอร์สที่แก้โดยตรง
- `dist/model.mjs` ตรวจข้อมูลนำเข้า บันทึก และอ่านจาก IndexedDB ใช้โมดูล `*-model.mjs` สำหรับตรรกะเฉพาะด้าน `dist/backup-client.mjs` ประสาน IndexedDB กับ API ในเครื่อง
- `server.mjs` และ `backup-store.mjs` ดูแล HTTP และประวัติไฟล์สำรอง เปิดด้วย `npm run dev` ที่ `http://127.0.0.1:4173` ใช้ Node 20+ ได้ทันที
- `tests/` ใช้ `node:test` และ `tests/fixtures/` สำหรับฉากทดสอบ `docs/` เก็บสเปก แผน หลักฐานการตรวจสอบ ไอเดีย และที่มาของเสียง

## แผนที่ฟีเจอร์

| ส่วนของโต๊ะ | ไฟล์ที่ควรเริ่มอ่าน |
|---|---|
| ใบเควส A4 การลาก ซูม และพิกัดตรา | `paper-format.mjs`, `interactions.mjs`, `desk-motion.mjs`, `stamp-placement.mjs`, `stamp-surfaces.mjs` |
| รางบน ลิ้นชักเก็บของร่วมด้านขวา เคาน์เตอร์ส่งเควสด้านซ้าย และแผงปิดเต็มจอ | `tool-rail.mjs`, `storage-tray.mjs`, `quest-reception.mjs`, `quest-reception-model.mjs`, `desk-shutter.mjs` |
| หน้าต่างอ่านหลายใบ แฟ้มหนัง และสมุดทั้งสองแบบ | `desk-windows.mjs`, `paper-reader.mjs`, `folio-windows.mjs`, `daily-book.mjs`, `notebook.mjs` |
| สีหนัง วงล้อ และตัวอย่างปกสด | `leather-colors.mjs`, `leather-folios.css`, `cover-editor.mjs` |
| รูปในใบเควส รูปวางเดี่ยว เควสก่อนหน้า และที่ทับกระดาษ | `quest-photos.mjs`, `photo-layout.mjs`, `photo-sheet.mjs`, `quest-dependencies.mjs`, `paperweight.mjs` |
| บัตรนักผจญภัย รอยไหม้ ฉากแสง ฝุ่น และเสียง | `adventurer-card.mjs`, `adventurer-model.mjs`, `burn-model.mjs`, `atmosphere.mjs`, `daypart-ambience.mjs`, `ambience.mjs`, `sound-catalog.mjs` |

ชื่อไฟล์ในตารางอยู่ใน `dist/` อ่านคู่กับ handler ใน `app.mjs` และเทสต์ของฟีเจอร์ก่อนเปลี่ยนพฤติกรรมที่หลายทางเข้าใช้ร่วมกัน

## หลักการใหญ่

1. ใช้ native modules และระบบเดิมก่อน การเพิ่ม dependency หรือ build step เป็นการเปลี่ยนสถาปัตยกรรมที่ต้องอยู่ในขอบเขตงาน
2. **ข้อมูลผู้ใช้สำคัญที่สุด** ห้ามทำให้เควส รูป ตรา แฟ้ม หรือตำแหน่งกระดาษสูญหาย
3. แยกการทดสอบจากข้อมูลจริงใน `../Questboard-Backups/` และ IndexedDB ของผู้ใช้ ใช้ข้อมูลสมมติ โฟลเดอร์สำรองชั่วคราว และโปรไฟล์เบราว์เซอร์แยก
4. **ส่งมอบแบบ local-only** ห้าม deploy อัปโหลด หรือเปลี่ยน `.openai/hosting.json` เว้นแต่ผู้ใช้สั่งชัดเจน
5. พื้นผิวและอุปกรณ์ใช้ CSS/SVG ของโปรเจกต์ เคารพภาพที่ผู้ใช้อัปโหลด เสียงที่เพิ่มให้บันทึกที่มาและสิทธิ์ในเอกสารเสียงที่เกี่ยวข้อง และเก็บไฟล์ License ตามเงื่อนไขของแหล่งเสียง

## ข้อมูลและไฟล์สำรอง

- รูปแบบข้อมูลเป็น `version: 1` และ `parseState` ปฏิเสธเวอร์ชันอื่น ฟิลด์ใหม่ต้องเป็นแบบ **ไม่ต้องเพิ่มเลขเวอร์ชัน**: ค่าที่ขาดใน legacy normalize เป็นค่าเริ่มต้น (เช่นตำแหน่งตราที่ไม่มีเป็น `null`) และไฟล์สำรองเก่าต้องยังเปิดได้
- แก้ตัวตรวจสอบที่ `dist/model.mjs` เป็นหลัก แล้วเพิ่มเทสต์นำเข้าข้อมูลรูปแบบเก่า
- อ่านขีดจำกัดของรายการ ภาพ โน้ต และขนาดไฟล์จากโมเดลและตัวเตรียมภาพที่เกี่ยวข้อง แยกขนาดไฟล์อัปโหลดก่อนย่อจากงบข้อมูลที่บันทึก หากข้อมูลใหม่เกินขีดจำกัด ให้คงข้อมูลเดิมและแจ้งเหตุผล
- การเขียนไฟล์สำรองใช้ revision แบบ optimistic (`baseRevision`, ตอบ 409 เมื่อขัดแย้ง) ห้ามทำลายกลไกนี้ และห้ามเขียนทับ `latest.json` ตรง ๆ นอก `backup-store.mjs`
- โฟลเดอร์สำรองเริ่มต้นคือ `../Questboard-Backups` (พาธสัมพันธ์กับโฟลเดอร์โปรเจกต์) ห้ามฮาร์ดโค้ดพาธเครื่องส่วนตัวเพิ่ม

## ความปลอดภัยของเซิร์ฟเวอร์

- `server.mjs` ฟังที่ `127.0.0.1` และตรวจที่มาของคำขอผ่าน `localRequest` คงการตรวจ `Host`, `Origin`, `Sec-Fetch-Site` ขีดจำกัด request และเงื่อนไขเขียนข้อมูลสำรองตามที่เซิร์ฟเวอร์กำหนด
- ตอบ `Cache-Control: no-store` กับ API และเสิร์ฟไฟล์ static จาก `dist/` เท่านั้น (กัน path traversal)

## UI และการโต้ตอบ

- ใบเควสสัดส่วน A4 (210:297) กว้าง 300 หน่วย ทุกที่ (โต๊ะ ลิ้นชัก หน้าขยาย แฟ้ม) ใช้ค่าจาก `paper-format.mjs` ไม่ใส่ตัวเลขซ้ำ
- พิกัดเควสบนโต๊ะ / ในลิ้นชัก / ตำแหน่ง UI ของหน้าต่างเอกสาร **เก็บแยกกัน** ห้ามผสมหรือเขียนทับ
- ตำแหน่งตราคือพิกัดในกระดาษ (paper-local) ต้องถูกต้องแม้ซูม เอียง หรือกระดาษกำลังเล่นอนิเมชัน (`stamp-placement.mjs`)
- สำหรับการกระทำที่แก้ข้อมูล ให้ commit ก่อนเล่นภาพยืนยัน คงผลลัพธ์เมื่อใช้ `prefers-reduced-motion` หรือเมื่อภาพเคลื่อนไหวยกเลิก และเก็บ timer, listener และ ghost ที่หมดอายุ
- ทุกการลากต้องมีทางเลือกด้วยคีย์บอร์ด (Tab, ลูกศร, Shift) และ Esc ต้องยกเลิกการลาก/ตราที่ถืออยู่ก่อนปิดหน้าต่าง
- ปุ่ม ช่องพิมพ์ และโน้ตบนกระดาษต้องใช้งานได้โดยไม่เริ่มลากหน้าต่าง/กระดาษ
- เสียงเริ่มหลังผู้ใช้โต้ตอบครั้งแรก เคารพปุ่มปิดเสียงและความดังรวม ห้ามเล่นเสียงย้อนหลังเมื่ออนิเมชันถูกยกเลิก
- ใช้ [กติกาการเคลื่อนไหว](motion-and-interaction.md) สำหรับการหยิบ ลาก วาง แสงและเสียง และ [แนวทางภาพ](design-system.md) คู่กับ [ขั้นตอนตรวจ UI](../workflows/ui-review.md) เมื่อเปลี่ยนหน้าตา

## เทสต์และการตรวจสอบ

- เทสต์ใช้ `node:test` กับโมดูลจริงจาก `dist/` และข้อมูลสมมติ ใช้ `npm test` สำหรับชุดรวมซึ่งตั้ง `--test-concurrency=1` ไว้แล้ว ดูวิธีแยกเบราว์เซอร์และเซิร์ฟเวอร์ใน [ขั้นตอนตรวจสอบ](../workflows/verify.md)
- **ทุกครั้งที่เพิ่มไฟล์ `.mjs` ใหม่ใน `dist/` ต้องเพิ่ม `node --check dist/<ไฟล์>.mjs` ลงสคริปต์ `check` ใน `package.json` ด้วย** เพราะรายการไฟล์ถูกระบุตายตัว
- ทำซ้ำอาการบั๊กก่อนแก้และเพิ่มเทสต์กันถอยเมื่อชุดเดิมไม่ครอบคลุม รายงานแยกว่าตรวจด้วยโมเดล DOM จำลอง เบราว์เซอร์ หรือดูภาพจริง

## วิธีทำงานตามธรรมเนียมของโปรเจกต์

- งานที่แก้หลายส่วนใช้สเปกและแผนใน `docs/superpowers/` เมื่อช่วยคุมขอบเขตและตรวจผล งานเล็กใช้ขั้นตอนใน workflow โดยตรง
- อัปเดต README เมื่อวิธีใช้งานเปลี่ยน อัปเดต backlog เมื่อทำไอเดียที่มีรายการอยู่ และลงหลักฐานที่มีประโยชน์ต่อการตรวจย้อนหลังใน `docs/verification.md`
- อ่าน `git status --short` ก่อนแก้ไฟล์ เก็บงานที่มีอยู่แล้วไว้ และตรวจ diff เฉพาะขอบเขตของงาน
- ไฟล์ `.gitignore` กัน `qa/`, `.local/`, `.sites-local/`, `*.log` ไว้ อย่า commit ไฟล์เหล่านี้
- Commit message เป็นรูปแบบ conventional (`feat:`, `fix:`, `style:`, ...) ตามประวัติเดิม

## สิ่งที่ไม่ควรทำ

- ไม่ล้าง IndexedDB หรือลบไฟล์สำรอง ไม่ย้ายโฟลเดอร์ `Questboard-Backups`
- ไม่แก้ `Start-Questboard.cmd`, `Launch-Questboard.ps1`, `Install-/Disable-Questboard-Autostart.ps1` เกินที่ผู้ใช้ขอ (เป็นสคริปต์ Windows)
- ไม่ restart โปรเซสที่ไม่ใช่ของโปรเจกต์นี้ (พอร์ต 4173) โดยไม่ตรวจก่อนว่าเป็น Node server ของ Questboard
- ไม่ลดคุณภาพหรือถอดฟีเจอร์เพื่อให้เทสต์ผ่าน
