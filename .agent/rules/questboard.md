# The Questboard — กฎสำหรับ Agent

กระดาน To-do ธีมกิลด์แฟนตาซี เขียนด้วย native ES modules (`.mjs`) + CSS ล้วน ไม่มี dependencies ไม่มี build step
เซิร์ฟเวอร์ Node (`server.mjs`, `backup-store.mjs`) มีหน้าที่เสิร์ฟ `dist/` และสำรองข้อมูลลงไฟล์เท่านั้น
ข้อความใน UI ข้อความ error และเอกสารเป็นภาษาไทย ตอบผู้ใช้เป็นภาษาไทยเสมอ

## โครงสร้างโปรเจกต์

- `dist/` — โค้ดฝั่งเบราว์เซอร์ทั้งหมด (deploy ได้ทันที) `app.mjs` เป็นตัวประกอบหลัก `model.mjs` คือโมเดลข้อมูลและตัวตรวจสอบ state
  โมดูลแยกตามฟีเจอร์ เช่น `folio-*`, `paper-*`, `stamp-*`, `quest-*`, `daily-book*`, `atmosphere`, `ambience`, `daypart-ambience`, `storage-tray`, `tool-rail`, `desk-windows` โดยมี `*-model.mjs` สำหรับตรรกะล้วนที่ทดสอบง่าย
- `tests/` — เทสต์ด้วย `node:test` (ไฟล์ `*.test.mjs`)
- `docs/` — `superpowers/specs` (สเปก), `superpowers/plans` (แผนงาน), `verification.md` (บันทึกการตรวจสอบ), `ideas-backlog.md`, ไฟล์ที่มาของเสียง
- ไม่มี `node_modules` ให้รันได้ด้วย Node 20+ โดยไม่ต้อง `npm install`

## หลักการใหญ่

1. **ห้ามเพิ่ม dependency หรือ build step** ถ้าจำเป็นจริงให้ถามผู้ใช้ก่อน
2. **ข้อมูลผู้ใช้สำคัญที่สุด** ห้ามทำให้เควส รูป ตรา แฟ้ม หรือตำแหน่งกระดาษสูญหาย
3. **ห้ามอ่าน แก้ หรือลบข้อมูลเควสจริง** (`../Questboard-Backups/`, IndexedDB ของเบราว์เซอร์ผู้ใช้) ทั้งตอนพัฒนาและทดสอบ ใช้ข้อมูลสมมติกับโฟลเดอร์ชั่วคราวเท่านั้น
4. **ส่งมอบแบบ local-only** ห้าม deploy อัปโหลด หรือเปลี่ยน `.openai/hosting.json` เว้นแต่ผู้ใช้สั่งชัดเจน
5. **ไม่ใช้ภาพหรือเสียงลิขสิทธิ์จากเกม** ลายพื้นผิว ไอคอน และตรากิลด์สร้างด้วย CSS/SVG เสียงใหม่ต้องบันทึกที่มาและลิขสิทธิ์ใน `docs/*-sources.md` และใส่ License ใน `dist/audio/...`

## ข้อมูลและไฟล์สำรอง

- รูปแบบข้อมูลเป็น `version: 1` และ `parseState` ปฏิเสธเวอร์ชันอื่น ฟิลด์ใหม่ต้องเป็นแบบ **ไม่ต้องเพิ่มเลขเวอร์ชัน**: ค่าที่ขาดใน legacy normalize เป็นค่าเริ่มต้น (เช่นตำแหน่งตราที่ไม่มีเป็น `null`) และไฟล์สำรองเก่าต้องยังเปิดได้
- แก้ตัวตรวจสอบที่ `dist/model.mjs` เป็นหลัก แล้วเพิ่มเทสต์นำเข้าข้อมูลรูปแบบเก่า
- ข้อจำกัดที่ต้องคงไว้ (นิยามใน `model.mjs`): `MAX_ITEMS` 500, `MAX_STAMPS` 30, `MAX_BACKUP_BYTES` 90 MB, `MAX_SUBQUESTS` 80, `MAX_QUEST_NOTES` 8000, รูปตรา ≤ 2 MB, รูปเควส ≤ 5 MB (ย่อด้านยาว ≤ 960 px) หากเต็มให้ปฏิเสธรายการใหม่ **ก่อน** แก้ข้อมูลเดิม
- การเขียนไฟล์สำรองใช้ revision แบบ optimistic (`baseRevision`, ตอบ 409 เมื่อขัดแย้ง) ห้ามทำลายกลไกนี้ และห้ามเขียนทับ `latest.json` ตรง ๆ นอก `backup-store.mjs`
- โฟลเดอร์สำรองเริ่มต้นคือ `../Questboard-Backups` (พาธสัมพันธ์กับโฟลเดอร์โปรเจกต์) ห้ามฮาร์ดโค้ดพาธเครื่องส่วนตัวเพิ่ม

## ความปลอดภัยของเซิร์ฟเวอร์

- `server.mjs` รับเฉพาะ loopback (`127.0.0.1`/`::1`) ตรวจ `Host`, `Origin`, `Sec-Fetch-Site` ผ่าน `localRequest` และจำกัดขนาด request ห้ามผ่อนเงื่อนไขเหล่านี้หรือเปิดฟังบน `0.0.0.0`
- ตอบ `Cache-Control: no-store` กับ API และเสิร์ฟไฟล์ static จาก `dist/` เท่านั้น (กัน path traversal)

## UI และการโต้ตอบ

- ใบเควสสัดส่วน A4 (210:297) กว้าง 300 หน่วย ทุกที่ (โต๊ะ ลิ้นชัก หน้าขยาย แฟ้ม) ใช้ค่าจาก `paper-format.mjs` ไม่ใส่ตัวเลขซ้ำ
- พิกัดเควสบนโต๊ะ / ในลิ้นชัก / ตำแหน่ง UI ของหน้าต่างเอกสาร **เก็บแยกกัน** ห้ามผสมหรือเขียนทับ
- ตำแหน่งตราคือพิกัดในกระดาษ (paper-local) ต้องถูกต้องแม้ซูม เอียง หรือกระดาษกำลังเล่นอนิเมชัน (`stamp-placement.mjs`)
- ทุกอนิเมชันต้องรองรับ `prefers-reduced-motion` (แสดงปลายทางทันที) และต้อง cleanup timer/listener/ghost เมื่อถูกยกเลิก re-render หรือ resize การเปลี่ยนข้อมูลต้อง commit **ก่อน** เล่นอนิเมชันเสมอ และความล้มเหลวของอนิเมชันต้องไม่บล็อกการบันทึก
- ทุกการลากต้องมีทางเลือกด้วยคีย์บอร์ด (Tab, ลูกศร, Shift) และ Esc ต้องยกเลิกการลาก/ตราที่ถืออยู่ก่อนปิดหน้าต่าง
- ปุ่ม ช่องพิมพ์ และโน้ตบนกระดาษต้องใช้งานได้โดยไม่เริ่มลากหน้าต่าง/กระดาษ
- เสียงเริ่มหลังผู้ใช้โต้ตอบครั้งแรก เคารพปุ่มปิดเสียงและความดังรวม ห้ามเล่นเสียงย้อนหลังเมื่ออนิเมชันถูกยกเลิก
- อนิเมชันและการลาก/วาง/เก็บของบนโต๊ะต้องทำตาม `.agent/rules/motion-and-interaction.md` เสมอ (ของต้องติดมือ ข้อมูลเปลี่ยนก่อนภาพ ยกเลิกได้ มี reduced-motion)
- งานดีไซน์ทุกอย่างต้องทำตาม `.agent/rules/design-system.md` (จานสี ตัวอักษร วัสดุ การเคลื่อนไหว น้ำเสียงข้อความ) และตรวจด้วย workflow `ui-review` ก่อนส่งงาน

## เทสต์และการตรวจสอบ

- เทสต์ใช้ `node:test` ให้ import โมดูลจริงจาก `dist/` และใช้ DOM จำลอง/ข้อมูลสมมติ รันแบบ `--test-concurrency=1` ห้ามรันขนาน
- **ทุกครั้งที่เพิ่มไฟล์ `.mjs` ใหม่ใน `dist/` ต้องเพิ่ม `node --check dist/<ไฟล์>.mjs` ลงสคริปต์ `check` ใน `package.json` ด้วย** เพราะรายการไฟล์ถูกระบุตายตัว
- แก้บั๊ก: เขียนเทสต์ที่ล้มก่อนแก้ แล้วค่อยแก้ให้ผ่าน (regression test)
- อย่าอ้างว่าตรวจ "ความลื่นของอนิเมชัน" หรือ "การใช้เมาส์จริง" ถ้าไม่ได้ดูในเบราว์เซอร์จริง ให้ระบุว่ายังไม่ได้ตรวจด้วยภาพ (ตามที่ `docs/verification.md` ทำมาตลอด)

## วิธีทำงานตามธรรมเนียมของโปรเจกต์

- งานใหญ่: เขียนสเปกใน `docs/superpowers/specs/YYYY-MM-DD-<ชื่อ>-design.md` และแผนใน `docs/superpowers/plans/YYYY-MM-DD-<ชื่อ>.md` (Goal / Architecture / Tech Stack / Global Constraints / Review Focus) ก่อนลงมือ
- เสร็จแล้วเพิ่มหัวข้อใหม่ที่ด้านบนของ `docs/verification.md` พร้อมวันที่ ผลเทสต์จริง (จำนวนผ่าน/ล้ม) และสิ่งที่ยังไม่ได้ตรวจ
- อัปเดต README จากมุมผู้ใช้ และถ้าต้องล้างแคช ให้เขียนว่า "หลังอัปเดตกด Ctrl+F5"
- ไอเดียที่ยังไม่ทำจดใน `docs/ideas-backlog.md` และทำเครื่องหมาย "— ทำแล้ว (วันที่)" เมื่อเสร็จ
- ไฟล์ `.gitignore` กัน `qa/`, `.local/`, `.sites-local/`, `*.log` ไว้ อย่า commit ไฟล์เหล่านี้
- Commit message เป็นรูปแบบ conventional (`feat:`, `fix:`, `style:`, ...) ตามประวัติเดิม

## สิ่งที่ไม่ควรทำ

- ไม่ล้าง IndexedDB หรือลบไฟล์สำรอง ไม่ย้ายโฟลเดอร์ `Questboard-Backups`
- ไม่แก้ `Start-Questboard.cmd`, `Launch-Questboard.ps1`, `Install-/Disable-Questboard-Autostart.ps1` เกินที่ผู้ใช้ขอ (เป็นสคริปต์ Windows)
- ไม่ restart โปรเซสที่ไม่ใช่ของโปรเจกต์นี้ (พอร์ต 4173) โดยไม่ตรวจก่อนว่าเป็น Node server ของ Questboard
- ไม่ลดคุณภาพหรือถอดฟีเจอร์เพื่อให้เทสต์ผ่าน
