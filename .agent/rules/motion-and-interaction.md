# The Questboard — อนิเมชันและการโต้ตอบ ("โต๊ะที่หยิบจับได้จริง")

หัวใจของโปรเจกต์: ผู้ใช้ **หยิบ ลาก วาง เก็บ เปิด ปั๊มตรา** ของบนโต๊ะ ไม่ได้กดปุ่มบนหน้าเว็บ
ทุกอนิเมชันต้องทำให้รู้สึกว่า "ของมีน้ำหนัก มีวัสดุ และอยู่ในมือเรา" ไม่ใช่แค่ทำให้ UI ดูมีชีวิต
เอกสารนี้สรุปจากโค้ดจริง (`desk-motion.mjs`, `paper-grip.mjs`, `paper-effects.mjs`, `interactions.mjs`, `paper-turn.mjs`, `motion.css`, `quest-effects.css`) ถ้าจะเพิ่มหรือแก้การเคลื่อนไหว ให้ใช้โครงสร้างเดิมเหล่านี้ก่อนเขียนใหม่

---

## 1. หลักการ 8 ข้อ

1. **ผู้ใช้คือคนขยับของ** การเคลื่อนไหวมาจากการกระทำของผู้ใช้เสมอ (หยิบ ปล่อย กด) อนิเมชันที่เกิดเอง ใช้ได้เฉพาะบรรยากาศ (แสง ฝุ่น เมฆ) ที่ปิดได้
2. **ของติดมือ ไม่หน่วง** ตำแหน่งใต้เมาส์/นิ้วต้องตรงกับพิกเซลที่จับไว้ตลอดการลาก ห้าม easing, spring หรือ smoothing กับพิกัด มีแค่ *การเอียง การงอ เงา* ที่ตอบสนองเพิ่มได้
3. **วัสดุต่างกัน ตอบสนองต่างกัน** กระดาษงอและเอียงตามมือ แฟ้มหนังแข็งกว่า ไม่เด้งแบบกระดาษ (`paperGripPose` ตั้งใจไม่ใช้กับแฟ้ม) ป้ายไม้และสมุดมีน้ำหนักของตัวเอง ห้ามใช้ท่าเดียวกับทุกวัตถุ
4. **การกระทำสำคัญต้องมีทั้งสามอย่างพร้อมกัน:** การเคลื่อนไหว (ภาพ) + ตัวบอกใบ้ก่อนปล่อย (affordance) + เสียง (cue) เช่น แฟ้มยกฝาเมื่อกระดาษเข้าใกล้, ลิ้นชักมีปากให้กระดาษไหลเข้า, เสียงกระดาษสไลด์
5. **เปลี่ยนข้อมูลก่อน แล้วค่อยเล่นอนิเมชัน** (`createPaperEffects` บันทึกไว้ในคอมเมนต์ว่า caller commit เควสทันที) อนิเมชันเป็นแค่ภาพบังตา ถ้าล้ม ถูกยกเลิก หรือหน้าต่างถูก resize ข้อมูลต้องอยู่ถูกที่เสมอ
6. **ยกเลิกได้ทุกเมื่อ** ผู้ใช้ลากต่อ กด Esc เปิดอย่างอื่น หรือเปลี่ยนขนาดจอ → ภาพชั่วคราวทั้งหมด (ghost, mask, timer, rAF, listener) ต้องถูกเก็บกวาดโดยไม่ทิ้งเศษและไม่เปลี่ยนข้อมูล
7. **เล็ก สั้น จบแน่นอน** (finite) "Small, finite motions belong to the paper and covers, never the hit area" พื้นที่รับคลิก/รับวางห้ามเคลื่อนตามอนิเมชัน ให้ขยับแค่ภาพของผิววัสดุ
8. **เคารพ reduced-motion** ปิดการเคลื่อนไหวแต่ **ผลลัพธ์ต้องครบ** (ของไปอยู่ที่ใหม่ทันที) เสียงยังเล่นตามปกติ (`store` และ `enter` ยิง cue แม้ reduced)

## 2. กริยาบนโต๊ะ — พฤติกรรมที่ต้องคงไว้

| กริยา | สิ่งที่เห็น | เวลา / easing อ้างอิง | หมายเหตุ |
|---|---|---|---|
| **หยิบ (grab)** | ของยกขึ้นเล็กน้อย scale ≈ 1.025 สว่างขึ้นนิด เงาใหญ่ขึ้น (`8px 23px 27px #180d0870`) | ทันที ไม่ ease | เก็บจุดที่จับเป็น `transform-origin` (`grabPoint`/`ghostPose`) ให้หมุน ซูม ยก ไม่ดึงของหลุดจากมือ |
| **ลาก (carry)** | เอียงตามความเร็วแนวนอน ±3° (`dragTilt`) กระดาษงอเป็น perspective ไม่เกิน ±3°/±4° พร้อมเงาเลื่อนตามมุมที่จับ | อัปเดตทุก pointermove | ใช้เฉพาะ `transform`/`opacity`/`filter` ห้ามแตะ layout ระหว่างลาก; ต้องคิดซูมโต๊ะ (`scale`) และมุมเอียงของใบเสมอ |
| **ชี้เป้าหมาย (hover target)** | แฟ้มยกฝาหน้า `rotateX(-28deg)` ลิ้นชักมีปากรับ | 260ms `cubic-bezier(.2,.75,.25,1)` | ใบ้ก่อนปล่อยเสมอ ถ้าปล่อยตรงนี้ไม่ได้ ห้ามแสดงว่ารับได้ (`storageTrayAccepts`) |
| **วางบนโต๊ะ (drop)** | ใบลงมาแตะ เอียงกลับเป็นมุมของมัน | 180–240ms; keyframe ต้นลง `cubic-bezier(.2,.8,.3,1)` | ตำแหน่งถูก clamp ตามมุมจริง (`rotatedClampPosition`) แล้ว commit |
| **เก็บเข้าลิ้นชัก (store)** | ใบเลื่อนเข้าหาปาก 180ms แล้วถูกกลืนผ่านขอบลิ้นชัก (ถูกตัดด้วย mask ที่ขอบ) 300ms | `cubic-bezier(.2,.72,.3,1)` แล้ว `cubic-bezier(.36,.08,.5,1)` | ตรวจตำแหน่งช่องรับทุกเฟรม (rAF) ถ้าช่องขยับ/ซ่อน/จอเปลี่ยนขนาด ให้ยกเลิก; แฟ้มใช้ `folderSlide` ไม่ใช่ `paperSlide` |
| **หยิบออก (retrieve)** | ใบคลี่ออกจากตำแหน่งที่คลิก ย่อ (≈0.18×0.08) → เกือบเต็ม (.76) → เต็ม | 600ms `cubic-bezier(.16,.75,.28,1)` | เสียง `paperUnfold` ทันที `paperDrop` ที่ ~456ms |
| **ปั๊มตรา (stamp)** | ตราตกลงเล็กน้อย กดแรง หมึกกระจาย | `stamp-in` .38s; `placed-fresh-ink` 320ms หน่วง 240ms | ตำแหน่งเป็นพิกัดในกระดาษ ห้ามย้ายตามอนิเมชัน; หมึกอยู่ใน `.quest-ink-layer` (multiply) |
| **ไฟมอด (extinguish)** | รอยไหม้สว่างวาบสั้น ๆ ก่อนมอดดับและจางหาย (`.paper-burn-extinguishing`) | 360ms `cubic-bezier(.22,.8,.24,1)` | เล่นเมื่อประทับตราเควสสำเร็จ/ยกเลิก ข้อมูลเปลี่ยนทันที รอยไหม้ใหม่ไม่มี เลเยอร์จำลองถูกลบอัตโนมัติ |
| **ฟื้นรอยไหม้ (rekindle)** | รอยไหม้ปรากฏนุ่มนวลเมื่อเควสกลับมา active | 400ms ease-out | ปิดเมื่อ prefers-reduced-motion |
| **เปิด/ปิดแฟ้ม** | แฟ้มคลี่ เชือกคลายทีละส่วน | เปิด 1020ms ปิด 880ms | ลำดับชิ้นส่วน: เชือก → ฝา → ใบ ต้องเล่นย้อนกลับตอนปิด |
| **พลิกหน้า / ปลดล็อก** | หน้ากระดาษม้วนเป็นขอบโค้ง | 780ms `cubic-bezier(.32,.05,.24,1)` | มุมพับยังเป็นปุ่มได้ขณะปั๊มตรา |
| **ดึงลิ้นชัก/ราง** | ลิ้นชักเลื่อนตามนิ้ว ปล่อยแล้วเปิดต่อถ้าถึง 40% ของระยะ (`shouldOpenDrawer`) | 380ms `cubic-bezier(.22,.8,.24,1)` ระหว่างดึงปิด transition | หูจับเป็นของจริง: ดึงได้ ไม่ใช่แค่กดสลับ |
| **กล่องโต้ตอบ** | ลอยขึ้น 9px จางเข้า | 180ms ease-out | เฉพาะ UI เงียบ ไม่ใช่ของบนโต๊ะ |

เส้นโค้งหลัก (เร็วแล้วชะลอ ให้ความรู้สึกวัตถุเสียดสีแล้วหยุด): `cubic-bezier(.22,.8,.24,1)`; โครงการนี้ใช้ตระกูลใกล้เคียงกัน (`.2,.75,.25,1`, `.2,.8,.3,1`, `.16,.75,.28,1`) ใช้ค่าที่มีอยู่ก่อน ห้ามใช้ `ease-in-out` หรือ `linear` กับท่าเคลื่อนที่ทั้งก้อน (ยกเว้น `linear` ระดับ options เมื่อ easing อยู่ในแต่ละ keyframe เหมือนที่ `app.mjs` ทำ)

## 3. กติกาเชิงเทคนิค

### โครงสร้างที่ต้องใช้
- **ghost:** ตอนลาก สร้างสำเนา `position: fixed` (เช่น `.quest-drag-ghost`) วางด้วย `ghostPose()` แล้วปล่อยตัวจริงอยู่กับที่จนวาง
- **`animateTransient(element, keyframes, options, {remove, onFinish})`** ใช้กับอนิเมชันชั่วคราวทุกอัน promise resolve เสมอ (แม้ยกเลิก/ไม่มี WAAPI) มีแค่ตัวล่าสุดที่เก็บกวาดและเรียก `onFinish` และใช้ `cancelMotion(el)` เพื่อยกเลิก
- **`createPaperEffects({reducedMotion, onCue, ...})`** คือที่อยู่ของ store/enter ฟีเจอร์ใหม่ที่เป็นตระกูลเดียวกัน (วัตถุถูกเก็บ/คลี่) ให้ต่อยอดที่นี่ ไม่เขียนซ้ำใน `app.mjs`
- ตรรกะคณิตศาสตร์ล้วน (ท่าทาง ขอบเขต การตัดสินว่าจะเปิดลิ้นชักไหม) ต้องเป็น **ฟังก์ชันบริสุทธิ์** ในไฟล์ `*-motion.mjs` / `interactions.mjs` / `*-model.mjs` เพื่อเทสต์ได้โดยไม่ต้องมีเบราว์เซอร์
- Web Animations API (`element.animate`) สำหรับท่าที่ซับซ้อน, CSS `@keyframes`/`transition` สำหรับสถานะคงที่ (hover ใบ้เป้าหมาย) ห้ามใช้ `setTimeout` ลำดับอนิเมชันถ้า WAAPI ทำได้ ถ้าจำเป็นต้องใช้ timer ต้องเก็บ id และยกเลิกตอน cleanup

### ประสิทธิภาพ
- อนิเมชันใช้ `transform`, `opacity`, `filter` เป็นหลัก ห้ามอนิเมต `left/top/width/height` ของของที่อยู่ใน layout (ยกเว้น ghost ที่เป็น fixed และถูกวางตำแหน่งต่อเฟรมโดยตั้งใจ)
- ใส่ `will-change` เฉพาะระหว่างลาก แล้วถอดทันทีหลังวาง (ตามที่ `.board-item.dragging` ทำ)
- อย่า `getBoundingClientRect()` ซ้ำในลูป pointermove ถ้าอ่านครั้งเดียวตอนเริ่มได้ ส่วน rAF watcher ของ `store` ยอมให้อ่านเพราะต้องตรวจช่องรับ
- รูปทรงตัวร่างกาย (hit area) ของของที่ลากต้องไม่ขยับระหว่างอนิเมชัน (ใช้ `touch-action: none` บน `.drag-handle` เฉพาะจุดจับ)

### พิกัด
- ทุกการลากต้องแปลงผ่านซูมของโต๊ะ (`dragPosition(..., scale, boardShift)`) และคิดมุมเอียงของใบ (`rotatedOrigin`, `rotatedClampPosition`) ห้ามสมมติว่า scale = 1 หรือ rotation = 0
- ตำแหน่งบนโต๊ะ / ในลิ้นชัก / ตำแหน่ง UI ของหน้าต่าง เก็บแยกกัน การวางในที่หนึ่งห้ามเขียนทับอีกที่
- คีย์บอร์ดต้องทำสิ่งเดียวกันได้ (ย้ายทีละขั้น เก็บ เปิด) โดยเล่นอนิเมชันชุดเดียวกันหรือแบบย่อ ไม่ใช่ข้ามไปเลย

### เสียง
- ผูกกับจังหวะสัมผัสด้วย `cue(name, signal, delay)` ผ่าน AbortController ถ้าอนิเมชันถูกยกเลิกก่อนถึงจังหวะ เสียงนั้นต้องไม่เล่นย้อนหลัง
- ชื่อเสียงใหม่ต้องเพิ่มใน `sound-catalog.mjs` พร้อมที่มา/ลิขสิทธิ์ใน `docs/`

## 4. ก่อนเพิ่มหรือแก้อนิเมชัน — เขียนสเปกสั้น ๆ ในแผนงาน

ตอบให้ครบทุกข้อก่อนเขียนโค้ด:

1. **วัสดุอะไร?** (กระดาษ/แฟ้มหนัง/ป้ายไม้/ตราหมึก/สมุด) แล้วมันควรเคลื่อนไหวต่างจากวัสดุอื่นอย่างไร
2. **กริยาอะไร?** ใช้กริยาเดิมในตารางหรือเพิ่มใหม่ (ถ้าใหม่ ต้องบอกว่าทำไมใช้กริยาเดิมไม่ได้)
3. **จากไหนไปไหน?** จุดเริ่ม จุดจบ และสิ่งที่ผู้ใช้เห็นระหว่างทาง (ใบ้ก่อน → เคลื่อนไหว → แรงกระทบ → นิ่ง)
4. **เวลาและ easing** ใช้ตระกูลเส้นโค้งเดิม ระยะรวม ≤ ~600ms (ยกเว้นพิธีกรรมใหญ่แบบแฟ้ม/สมุด)
5. **เสียง** จังหวะไหน
6. **ข้อมูลเปลี่ยนเมื่อไร?** ต้องก่อนอนิเมชันเริ่ม
7. **ยกเลิกแล้วเกิดอะไร?** ระบุตัวที่ต้องเก็บกวาดทีละอย่าง
8. **reduced-motion** ผลลัพธ์สุดท้ายคืออะไร เสียงเล่นหรือไม่
9. **เทสต์:** ส่วนที่เป็นคณิตศาสตร์ต้องมีเทสต์ฟังก์ชันบริสุทธิ์ ส่วนวงจรชีวิต (เริ่ม/ยกเลิก/จบ/reduced) ต้องมีเทสต์ด้วย element จำลองที่มี `animate()` ปลอม เหมือนเทสต์เดิมในโปรเจกต์

## 5. สิ่งที่ห้ามทำกับการเคลื่อนไหว

- ทำให้ของ "ลื่นตามหลังเมาส์" (lerp/spring กับพิกัด) หรือหน่วงเวลาก่อนเริ่มลาก
- bounce/elastic ยืดหยุ่นแบบการ์ดแอป ของกระดาษกับหนังไม่เด้งเหมือนยาง มีแค่ overshoot เล็กน้อยแล้วนิ่ง (เช่น .72 → 0 ใน `translate` ตอนเก็บเข้าที่)
- อนิเมชันเข้าจอแบบ fade-slide-up ทุกชิ้น หรือ hover ขยับทุกอย่าง
- อนิเมชันที่บล็อกการใช้งาน: ผู้ใช้ต้องหยิบชิ้นต่อไปได้ระหว่างที่ชิ้นก่อนกำลังลงที่
- ให้ภาพอนิเมชันเป็นตัวตัดสินสถานะข้อมูล (เช่นรอ `finished` ก่อนค่อยบันทึก)
- ใช้ท่าเดียวกันกับแฟ้ม กระดาษ และป้าย
- ปล่อย ghost/mask/คลาสชั่วคราวค้างใน DOM หลังเสร็จหรือถูกยกเลิก
- เปลี่ยนแปลงพิกัดที่เก็บจริงเพื่อให้อนิเมชันสวย (อนิเมชันมีผลทางภาพเท่านั้น)

## 6. กติกากลางและการตรวจสอบอัตโนมัติ (Phase 1)

- **ค่าเวลาและ easing กลาง (`dist/motion-tokens.mjs` + `dist/motion-tokens.css`):** ห้ามตั้งค่าเวลาหรือ `cubic-bezier(...)` ใหม่กระจัดกระจายเอง ให้ import จาก `MOTION_DURATION`, `MOTION_EASING`, `MOTION_TIMING` หรือใช้ตัวแปร CSS (`--dur-*`, `--ease-*`) แทน
- **ทุก `.animate(` ต้องผ่าน `animateTransient`:** ห้ามเรียก `element.animate(...)` โดยตรงในโมดูลอื่นนอก `dist/desk-motion.mjs` เพื่อให้ทุกอนิเมชันมีการยกเลิก (cleanup) ที่ปลอดภัยและถูกตรวจสอบโดย `tests/motion-governance.test.mjs`
- **ตรวจ reduced-motion เสมอ:** ทุกโมดูลที่เรียก `animateTransient` ต้องตรวจ `reducedMotion` / `prefers-reduced-motion` ก่อนเล่นอนิเมชัน
- **เครื่องมือวัดเฟรม (`?motion-debug`):** เปิดผ่าน URL `?motion-debug` (`dist/motion-debug.mjs`) เพื่อดู FPS, เฟรมที่เกิน 24ms, Long Tasks และจำนวน WAAPI ที่ทำงานอยู่ โดยไม่มีค่าใช้จ่ายเมื่อไม่ได้เปิดพารามิเตอร์นี้
