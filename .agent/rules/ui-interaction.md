# The Questboard — การออกแบบ UI บนโต๊ะกิลด์

เวลาออกแบบของใหม่ ให้คิดว่าผู้ใช้จะจับตรงไหน ย้ายไปไหน และต้องเปิดดูใกล้ ๆ หรือไม่ ใบเควส แฟ้ม สมุด และภาพควรจัดวางได้อิสระ ส่วนรางเครื่องมือ ลิ้นชัก และแผงไม้เคลื่อนตามแนวของชิ้นนั้น ปุ่มและฟอร์มใช้พื้นที่เท่าที่จำเป็นเพื่อให้ยังเห็นโต๊ะและของที่วางอยู่

ใช้คู่กับ [แนวทางภาพ](design-system.md) และ [กติกาการเคลื่อนไหว](motion-and-interaction.md) เลือกเฉพาะการโต้ตอบที่เหมาะกับหน้าที่ของวัตถุในงานนั้น

## จุดจับและการจัดวาง

| สิ่งที่ผู้ใช้จับ | แนวทางออกแบบ |
|---|---|
| ใบเควส รูป ป้าย และของวางบนโต๊ะ | ให้จับจากขอบหรือบริเวณว่างบนตัววัตถุ เห็นเคอร์เซอร์มือเมื่อจับได้ และลากไปวางได้ทุกทิศทางในพื้นที่ที่รองรับ |
| แฟ้ม สมุด หรือใบเควสที่เปิดอ่าน | ให้จับจากขอบปกหรือขอบกระดาษที่เห็นอยู่ จัดปุ่มปิด พลิกหน้า และช่องกรอกให้คลิกหรือแตะได้ตามปกติ |
| ราง ลิ้นชัก และแผงไม้ | ให้มือจับเคลื่อนตามชิ้นงานและแนวราง ใช้ทั้งคลิกหรือแตะเพื่อเปิดปิด และลากเพื่อควบคุมระยะเปิดตามรูปแบบของชิ้นนั้น |
| ตราที่ถืออยู่ เครื่องมือจัดรูป และจุดปรับขนาด | แสดงให้เห็นว่ากำลังใช้เครื่องมือไหน ให้การคลิกหรือลากทำหน้าที่ของเครื่องมือนั้น และมีทางออกจากโหมดที่ชัดเจน |

- ใช้ระยะขยับขั้นต่ำเพื่อแยกคลิกออกจากการลาก จับจุดเดิมบนวัตถุไว้ใต้เมาส์ตลอด แม้โต๊ะกำลังซูม เลื่อน หรือวัตถุเอียง ใช้พิกัดของพื้นที่จริงและตัวช่วยเดิมใน `interactions.mjs` กับ `desk-motion.mjs`
- วางขอบเขตตามขนาดจริงของวัตถุและพื้นที่ที่มองเห็น ตรวจทั้งขอบซ้ายและขวา ชั้นแสงและเงาตกแต่งควรปล่อยให้ตัวชี้ผ่านถึงวัตถุได้
- แสดงช่องรับก่อนปล่อยเมื่อปลายทางรับวัตถุนั้นได้ ใช้ขอบช่องหรือปากแฟ้มเป็นสัญญาณ และคำนวณจากพื้นที่รับจริงขณะที่ลิ้นชักเคลื่อนอยู่ ตัวอย่างเช่น ถาดส่งเควสรับใบเควส ส่วนลิ้นชักเก็บของรองรับหลายชนิดตามกติกาของระบบ
- วางบนโต๊ะแล้วบันทึกตำแหน่งใหม่ เก็บเข้าช่องแล้วบันทึกในพื้นที่นั้น การปล่อยผิดช่อง กด Esc หรือเสียการจับตัวชี้ ให้คืนต้นทางหรือคงข้อมูลเดิมตามความหมายของท่าทาง ล้างสถานะชั่วคราวและเอาภาพจำลองออกเมื่อจบ

## ซูม ขยาย และปรับขนาด

| การกระทำ | ผลที่ผู้ใช้ควรเห็น |
|---|---|
| **ซูมโต๊ะ** | เห็นของบนโต๊ะใหญ่หรือเล็กพร้อมกัน มีปุ่มย่อ ขยาย และคืนขนาด ใช้จุดที่กำลังดูเป็นหลักยึด หากเพิ่มซูมจากเคอร์เซอร์หรือสัมผัส ให้ยึดตรงจุดนั้น ปุ่มที่รางและมือจับยังอยู่ในขนาดที่เข้าถึงได้ |
| **ขยายเพื่ออ่าน** | เปิดใบเควส แฟ้ม สมุด หรือรูปในมุมมองที่พอดีกับพื้นที่ เห็นปุ่มปิดและพื้นที่จับ เมื่อปิดแล้วกลับไปหาวัตถุบนโต๊ะตามตำแหน่งเดิม |
| **ปรับขนาดของที่วางบนโต๊ะ** | ใช้จุดจับที่มุมกับวัตถุที่รองรับ เช่น ภาพวางเดี่ยว ล็อกสัดส่วนภาพและบันทึกขนาดเมื่อยืนยัน ใบเควสยังใช้สัดส่วน A4 จาก `paper-format.mjs` |

เก็บพิกัดโต๊ะ พิกัดในลิ้นชัก ตำแหน่งหน้าต่าง และค่าซูมตามเจ้าของข้อมูลของแต่ละส่วน การซูมหรือเปิดอ่านมีผลกับมุมมอง การบันทึกขนาดหรือตำแหน่งของวัตถุเกิดจากการจัดวางโดยตรง

## เปิดหลายชิ้นและใช้งานบนจอเล็ก

- ให้เอกสารอ่านพร้อมกันได้และยกชิ้นที่โต้ตอบขึ้นหน้า ใช้ `desk-windows.mjs` จัดลำดับและตำแหน่งของหน้าต่าง เอกสารที่เปิดอยู่ควรมีขอบจับหรือวิธีปิดที่เข้าถึงได้หลังหมุนจอหรือปรับขนาดหน้าต่าง
- ใช้เมนูและกล่องโต้ตอบเมื่อการกระทำต้องใช้ฟอร์มหรือต้องรอการตัดสินใจ เช่น แก้ชื่อหรือยืนยันการลบ วางคำสั่งที่ใช้เฉพาะชิ้นไว้บนชิ้นนั้นหรือในเมนูตามบริบท
- ให้ Tab ไปถึงจุดจับและปุ่มสำคัญ ใช้ปุ่มลูกศรย้ายตามรูปแบบเดิม มีปุ่มหรือคำสั่งสำหรับการย้าย เก็บ และซูมที่คนใช้คีย์บอร์ดหรือแตะจอทำได้ ใช้ Esc ยกเลิกท่าทางที่กำลังทำก่อนจัดการหน้าต่างบนสุด
- บนจอสัมผัส ให้เลื่อนเนื้อหาและพิมพ์ได้ตามปกติ ใช้ `touch-action: none` เฉพาะจุดจับที่จำเป็น ตรวจขอบจอและพื้นที่เลื่อนเมื่อหน้าต่างหลายชิ้นซ้อนกัน
- ให้เงา ขอบ และเสียงช่วยบอกจังหวะหยิบ วาง หรือเก็บ พิกัดระหว่างลากตอบสนองทันที และโหมดลดการเคลื่อนไหวยังสื่อผลของการกระทำได้ครบ
